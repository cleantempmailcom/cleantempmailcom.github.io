How to Test a Welcome Email: Subject, Links, Images and Content Checklist

Verification emails get tested; welcome and notification emails often do not. Links pointing at a staging site, unreplaced name variables and broken images are the kind of bugs users find first. This checklist covers a welcome email and shows how to read each real message in an isolated temporary inbox.

Setup: read the real email in a real inbox

Checking the template in code is not enough: variables, the sending service and rendering all shape the final message. It is more reliable to let a test account receive a real email. Give each case its own address: CleanTempMail inboxes can be random or use a custom prefix, so put the environment or case name in the prefix. The web inbox is free with no sign-up, refreshes automatically or manually, and shows message bodies and attachments.

To fetch mail in automation see the email testing API guide (the REST API uses paid one-time keys, with a shared ct-test key to try it); for the signup flow itself see the signup verification test cases.

02

Check 1: recipient, sender and subject

  • The email goes only to the address entered at signup: no extra or missing sends.
  • Sender name and subject follow your standards, with no leftover “test” or “TODO” text.
  • Variables in the subject (such as the name) are replaced, including when the name is empty or very long.
03

Check 2: body and variables

  • Greeting, dates and product name are right, with no raw template markers.
  • Names with special characters, non-Latin scripts or emoji display correctly.
  • The language of the email matches the account’s language setting.
04

Check 3: where the links go

  1. Open every link and confirm it targets the current environment, not dev or staging.
  2. Sign-in, help centre and unsubscribe links work.
  3. If links carry tracking parameters, confirm they are complete and the page still loads.
05

Check 4: images, attachments and tracking

External images in emails sometimes fail to load, and some carry tracking pixels. CleanTempMail’s tracking protection blocks external images in emails, so remote images may not appear here. Treat that as the “images blocked” view: check that text and alt text still read clearly and buttons stay usable. If the email has attachments, open them from the inbox and confirm name and content.

06

Check 5: duplicate sends and counts

  • One signup should leave exactly the expected number of emails, never two welcome emails.
  • Resubmitting the signup form should not send duplicates.
  • Delete single messages or clear the inbox to keep the next case clean. For repeat signups see the duplicate email signup test cases.
07

When the welcome email does not arrive

  1. Confirm the recipient matches the form value exactly.
  2. Refresh the inbox manually once.
  3. When polling via API, log the number of empty polls to separate “never sent” from “did not wait long enough”.
08

Frequently asked questions

What should I check in a welcome email?

Recipient, sender, subject, body variables, link targets, images and attachments, and the number of emails sent.

Do I need to sign up for CleanTempMail to check test emails?

Not for manual use: the web inbox is free with no sign-up.

Why are images missing from the email?

Tracking protection blocks external images in CleanTempMail; use it to check the email still reads well without them.

Can I fetch emails automatically?

Yes, CleanTempMail offers a paid REST API; see the email testing API guide.

Are emails kept permanently?

No, emails are temporary and not stored permanently.
