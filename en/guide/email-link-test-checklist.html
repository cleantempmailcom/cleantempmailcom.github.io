Wrong Domain in Email Links? A Test Checklist for Verification Emails

The email copy looks right, but the link jumps to production, or the token is truncated or escaped. These bugs are common during integration and easy to miss. This checklist covers what to check for each kind of link and how to use a temporary inbox to get a clean email for every test.

01

Why email links deserve their own tests

Links are assembled by the backend from configuration, routes and templates. A missing environment variable, a hard-coded domain or an unencoded parameter sends users to the wrong page. API tests rarely catch this; only a real email does.

02

What to check

  • Domain and protocol: emails from test or staging should link to that environment, not production, over https. See managing test emails in staging.
  • Parameter integrity: are token, email and redirect parameters complete, and are special characters (plus, equals, &) encoded correctly?
  • Plain-text and HTML parts: if the template has both, links should match.
  • Button and visible URL: does the button point to the same place as the plain "copy this link" address?
  • One-time use and expiry: see one-time link prefetch test cases.
  • Localization: do localized emails carry the right language parameter?
03

Check links in a temporary inbox

  1. Create a test address: open CleanTempMail, no signup needed, and generate a random address or a custom prefix that identifies the case.
  2. Trigger the email: run signup, password reset or another flow with that address.
  3. Open the message: the inbox refreshes automatically or manually; read the body and copy the link to check domain and parameters.
  4. Record the result: note the faulty link with its environment.
  5. Clean up: emails are temporary and not stored permanently; delete the message or clear the inbox.

To automate this, CleanTempMail offers a paid REST API; see the email testing API guide.

04

Cases worth covering

  • Trigger emails in each environment (dev, test, staging) and check the domain.
  • Addresses containing a plus or dot: are parameters still correct?
  • Open the link in a fresh browser: does it depend on an existing session?
  • With external images blocked, does the link still work? CleanTempMail has tracking protection that blocks external images.
  • Trigger several emails: does the newest link work?
05

Habits that reduce misses

Add "email link domain" to your pre-release checks and rerun the link cases whenever the template or site-address config changes. Use a separate inbox per case so old messages do not confuse results.
