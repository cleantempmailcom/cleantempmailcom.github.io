How to Test Email Verification Codes with Playwright

Playwright can click buttons and fill forms, but it cannot receive email. The verification code or confirmation link step needs an inbox your test can create and read itself. This guide covers the structure of the flow and the usual pitfalls.

Why end-to-end tests get stuck at the email step

In a signup flow the hardest part to automate is rarely the form, it is the email: the test needs an address that can receive mail, has to wait for delivery, then extract a code or link from the body. A fixed real mailbox makes tests fight over messages, and a shared one makes them read stale mail.

A steadier approach is one disposable inbox per test. The CleanTempMail web inbox is free and needs no signup, so you can walk the flow by hand first; for scripts, use the paid REST API.

02

Walk through it by hand first

Before writing code, open CleanTempMail, generate an address (random or custom prefix), sign up in your test environment, and note how long the email takes, what the body looks like and where the code or link sits. That tells you what the script must match, and may expose problems in the email itself.

03

The basic shape of the test

  • Create an address: generate a separate one at the start of each test; put the test name in a custom prefix to ease debugging.
  • Fill and submit: use Playwright to enter that address on the signup page.
  • Poll the inbox: set a total timeout and a polling interval, and stop as soon as a message arrives.
  • Extract the code or link: use a regex or parser on the body.
  • Finish verification: type the code, or page.goto the confirmation link, then assert the signed-in state.
  • Clean up: delete the test emails at the end.

Wait with an explicit timeout and retries, not a fixed sleep. With the paid API every poll uses request quota, empty inbox included, so do not set the interval too short.

04

Do not only test the happy path

  • Wrong or expired codes and their messages; see the OTP verification test cases.
  • After "resend", only the newest email should work.
  • What happens when the link is opened twice.
  • Whether the page explains clearly when no email arrives.
05

Running in parallel

Playwright can run several workers at once. As long as each test has its own inbox, none reads another test's mail; if workers share one address you get intermittent failures, covered in tests receiving the wrong verification email. The same idea applies to Cypress; see testing verification emails in Cypress.

06

Debugging failures

  • On failure, print the subjects already in the inbox to tell "never sent" from "sent but not matched".
  • The CleanTempMail inbox blocks external images; text codes are unaffected, but a code placed only inside an image cannot be read by a script.
  • Try the shared test key ct-test to learn the API; its quota is shared with other users, so use your own purchased key for real CI.
07

FAQ

Do I need a real mailbox for Playwright email tests?

No. A CleanTempMail temporary inbox can receive the verification email; it is free and needs no signup.

How do I receive email inside a script?

Use the CleanTempMail paid REST API to create addresses, poll the inbox and read the body.

Can tests run in parallel?

Yes, provided each test uses its own address so none reads another test's email.

Are emails kept forever in the temporary inbox?

No. Emails are temporary and not stored permanently.
