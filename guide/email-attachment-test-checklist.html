邮件附件怎么测？账单、报表与导出文件的测试清单

发票、对账单、数据导出、订单凭证……很多系统邮件都带附件。附件出错往往比正文出错更隐蔽：邮件发出去了，文件却是空的、名字乱码或打不开。这篇文章给出一份可以直接套用的附件测试清单。

01

为什么附件需要单独测

正文通常由模板渲染，附件却常常来自另一条链路：报表任务、文件存储、PDF 生成服务。任何一环出问题，邮件仍然会“成功”发出，只是附件有问题。因此测试里不能只断言“收到了邮件”。

如果你还没有搭好基础流程，可先看注册验证邮件的测试用例清单，再把附件检查加进去。

02

五类检查：名称、类型、大小、内容、下载

  • 文件名：是否带有预期的前缀和日期，中文或特殊字符是否乱码。
  • 文件类型：扩展名与实际格式是否一致，例如声明为 PDF 的文件确实能按 PDF 打开。
  • 文件大小：不应为空，也不应异常偏大；大文件场景要确认是否改为下载链接。
  • 文件内容：抽查关键字段，如金额、日期、订单号，是否与触发流程的数据一致。
  • 下载与打开：在收件箱里能否正常查看或保存，保存后文件能否打开。
03

用临时收件箱做一次手动检查

  1. 准备地址：在 CleanTempMail 网页收件箱生成地址，免费且无需注册，可使用随机地址，也可以自定义前缀，比如用例名称。
  2. 触发邮件：让被测系统向这个地址发送带附件的邮件。
  3. 刷新并打开：手动刷新或开启自动刷新，打开邮件正文，在附件区查看附件。
  4. 逐项核对：按上面的五类检查记录结果。
  5. 清理：测试完成后删除这封邮件，或清空收件箱。

先手动跑通一次，再决定哪些检查值得放进自动化。

04

哪些检查适合自动化

文件名、类型、大小这类规则明确的检查适合自动化；内容抽查可以只断言几个关键字段。自动化时请为每次运行准备独立的地址，避免读到别的用例留下的邮件，做法见给每个用例一个独立临时邮箱。

CleanTempMail 提供付费 REST API，可用于自动化收信；每次轮询都会计入请求额度，包括空轮询，因此建议设置等待上限，具体见API 自动化测试指南。

05

常见问题与排查思路

  • 邮件到了但没有附件：检查生成文件的任务是否在发信前完成。
  • 附件打不开：对比文件大小和类型，判断是生成失败还是传输编码问题。
  • 邮件迟迟没到：附件较大时可能更慢，请设置合理的等待上限，排查见延迟邮件的测试用例。
  • 测试数据：附件里不要放真实用户数据，使用测试数据即可。
06

常见问题

临时收件箱能查看邮件附件吗？

可以，CleanTempMail 网页收件箱支持查看邮件正文和附件。

需要注册 CleanTempMail 吗？

网页收件箱免费，无需注册。

附件测试一定要自动化吗？

不一定。建议先手动跑通，再把文件名、类型、大小这类规则明确的检查自动化。

邮件会一直保留吗？

不会。邮件是临时的，不会永久保存，需要留存的证据请自行保存。

自动化收信要付费吗？

网页收件箱免费；通过 REST API 自动收信需要购买 API 密钥，也有共享的测试密钥可供尝试。
