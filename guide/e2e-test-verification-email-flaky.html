E2E 测试收验证码邮件总是失败？Playwright 稳定等待邮件的做法

登录或注册用例一到“输入邮件验证码”这一步就偶尔失败，多半不是邮件丢了，而是测试等得不对。本文以 Playwright 为例，讲怎样用唯一地址、有时限的轮询和精确断言，把这类 flaky 用例稳下来。

01

验证码用例为什么会 flaky

常见原因只有几类：固定 sleep 太短，邮件还没到就去读；多个并行任务共用同一地址，读到了别人的邮件；收件箱里残留上一次的验证码，被误当成这一次的；超时之后没有任何信息，不知道是应用没发、邮件没到还是断言写错。

这几类问题的解法都是同一个思路：让每次运行只关心属于自己的那一封邮件，并给等待设一个明确的上限。

02

第一步：每次运行一个唯一地址

CleanTempMail 的网页收件箱免费、无需注册，支持随机地址和自定义前缀；需要在代码里读取时，使用付费 API。把运行 ID 或用例名写进前缀，例如 e2e-login- 加一段随机串，并行任务就不会互相干扰。

地址和域名的具体可用情况以官网当前说明为准。需要自己控制域名时，参考自有域名临时邮箱配置指南。

03

第二步：用 expect.poll 做有时限的等待

Playwright 自带 expect.poll，可以按间隔反复执行一个函数，直到断言通过或超时。下面是示意代码，其中 fetchMessages 是你按官方 API 文档自己封装的适配函数，这里不假设具体的接口路径和字段：

import { test, expect } from '@playwright/test';

test('login with emailed code', async ({ page }) => {
  const address = makeAddress('e2e-login');   // 含随机串的唯一地址
  await page.goto('/login');
  await page.getByLabel('Email').fill(address);
  await page.getByRole('button', { name: 'Send code' }).click();

  const code = await expect.poll(async () => {
    const msgs = await fetchMessages(address); // 你的适配函数
    const m = msgs.find(x => x.subject.includes('verification'));
    return m ? extractCode(m.body) : null;
  }, { timeout: 60_000, intervals: [2_000, 3_000, 5_000] })
    .not.toBeNull();
  // 再用提取到的验证码继续后面的步骤
});

要点：上限（这里 60 秒）和间隔都写明；返回 null 表示“还没到”，而不是通过。注意付费 API 的每次轮询都会计入额度，包括空结果，间隔不要设得过密，额度估算见API 自动化测试指南。

04

第三步：断言这封邮件属于这次运行

  • 收件地址等于本次生成的唯一地址。
  • 主题或发件人符合预期，而不是只要“有邮件”。
  • 验证码的格式（位数、字符类型）正确，再去填表单。
  • 如果邮件里是链接，先检查主机名属于你的测试环境，再访问。

注册类用例还可以对照注册验证邮件测试用例清单，补齐重发、重复注册等场景。

05

第四步：让超时说清楚原因

超时失败时，报告里至少带上：阶段（应用触发、等待、解析）、已等待时长、最后一次轮询得到的邮件数量。不要把完整验证码和带凭据的链接写进日志。

若确认应用已发送而收件箱始终为空，按收不到邮件的排查步骤区分发送端、地址和收件箱问题，再决定是否提 bug。

06

放进 CI 之前

  • API 密钥放在 CI 的密钥配置里，只在服务端任务使用，不要写进仓库、查询参数或日志。
  • 官网提供的共享试用密钥只适合体验，不要作为持续测试的额度来源。
  • 用例结束后删除本次邮件，失败时先保存脱敏证据再清理。
  • 只对自己的产品和测试环境做这类测试，第三方网站请遵守其规则。
07

常见问题

Cypress 或 Selenium 也能用这个思路吗？

可以。核心是唯一地址、有时限的轮询和精确断言，与具体框架无关；Playwright 的 expect.poll 只是一种写法。

为什么不直接 sleep 十秒？

固定等待要么太短导致偶发失败，要么太长拖慢整个流水线。有上限的轮询在邮件一到就继续。

并行跑多个测试会串信吗？

每个运行使用含随机串的唯一地址，并断言收件地址，就不会读到别人的邮件。

轮询会消耗额度吗？

付费 API 的每次轮询都计入额度，包括空结果，所以要设置合理的间隔和上限。

网页收件箱能用于自动化吗？

网页收件箱适合手工检查；需要在代码里读取邮件时，使用官网的 API。
