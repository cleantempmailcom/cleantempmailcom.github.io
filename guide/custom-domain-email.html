自有域名临时邮箱配置指南：MX、验证与测试

接入自有域名前，先确定哪些地址应该交给临时收信服务。为测试用途规划独立的邮件域名，可以让日常收信与测试收信更容易区分。以下是一份配置与验收清单。

01

先选择要接入的邮件域名

假设日常邮箱使用 name@example.com，测试地址可以规划为 run123@qa.example.com。这里的域名是示例，需要替换为你实际拥有并能管理 DNS 的域名。

在 DNS 控制台检查目标域名已有的 MX 记录，并保存当前配置。不要把正在承担公司日常收信的域名直接改为测试用途。如果选择子域名，还要在提交前确认 CleanTempMail 当前接入流程支持你选择的名称。

02

MX 记录决定这一个邮件域名如何收信

MX 是接收邮件的路由记录。它的名称对应邮件地址中 @ 后面的域名，目标是邮件服务器主机名，不是网页链接；记录优先级用于比较邮件服务器的优先顺序。

网站的 A、AAAA 或 CNAME 记录与邮件的 MX 记录承担不同作用。你在浏览器中能打开某个网站，并不能据此判断那个域名的收信路由正确。

不要直接复制猜测的配置值

MX 目标、优先级和验证要求应从 CleanTempMail 的当前接入界面获取。将当前界面提供的值应用到你选择的邮件域名，不要把示例域名当成实际收信配置。

03

按配置、验证、投递的顺序进行

  1. 确认目标域名由你控制，列出原有邮件服务与记录。
  2. 打开官方域名接入说明，获取需要填写的 MX 与验证信息。
  3. 在 DNS 服务商处修改对应名称的记录，检查是否被自动追加域名后缀。
  4. 向 CleanTempMail 提交域名并完成验证。
  5. 仅在验证通过后，为这个域名建立本次测试地址。
  6. 使用你有权操作的发送方寄送测试邮件，记录投递结果。

CleanTempMail 的域名接入与验证入口以 官方帮助 为准。DNS 配置可见与实际邮件送达需要分别检查。

04

如何读取 DNS 检查结果？

在支持 dig 的终端中，下面的命令可以查看示例测试域名的 MX 记录。查询 DNS 本身不会修改记录，也不会发送邮件。

dig MX qa.example.com +short

比较返回的目标和优先级与官方接入要求。没有结果时，检查名称与记录是否保存到正确的 DNS 区域。返回旧值时，检查本地或递归解析器的缓存，并核对该域名实际使用的权威 DNS 服务。

DNS 服务商可能使用不同的名称填写方式，例如只输入 qa，或者输入完整域名。按控制台说明填写，不要让名称变成 qa.example.com.example.com。

05

上线前的验收与回退记录

  • 保存配置前后的记录、修改时间和负责人员。
  • 确认日常邮箱仍然按原来路径收信。
  • 让测试邮件使用不同的主题或运行 ID，避免混淆。
  • 完成一次发信、收信、阅读和清理流程。
  • 出现问题时先对照原配置与投递日志，再决定是否恢复记录。

如果 DNS 看起来正确但邮件仍未出现，继续查看 收不到邮件的排查指南。DNS 记录不是账户访问控制，也不应被当成长期保存测试邮件的承诺。

需要在自己的应用中重复执行验收时，可参考API 邮件自动化测试流程，分别记录投递、内容检查与清理结果。
