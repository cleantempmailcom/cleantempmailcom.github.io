修改登录邮箱怎么测？更换邮箱验证流程的测试用例清单

“修改邮箱”是账号安全里很容易出错的功能：新邮箱没验证就生效、旧邮箱收不到通知、邮箱被别人占用却没有提示。要测完整流程，需要同时有“旧邮箱”和“新邮箱”两个真实收件箱。本文给出一份测试用例清单，并说明如何用两个独立的临时邮箱完成。

01

先准备：两个独立的收件箱

用 CleanTempMail 生成两个地址：一个当作旧邮箱用来注册测试账号，一个当作新邮箱用来接收确认邮件。收件箱可以随机生成，也可以自定义前缀，例如把 old 和 new 写进前缀，方便区分。网页收件箱免费，无需注册，可以自动或手动刷新，能查看邮件正文和附件。

如果要在自动化脚本里取信，参考邮件测试 API（REST API 为付费一次性密钥，另有共享的 ct-test 密钥可供试用）；注册本身的用例见注册验证邮件测试用例。

02

用例一：新邮箱验证

  1. 登录后提交新邮箱，确认新邮箱收到确认邮件，并且邮件里的链接指向当前环境。
  2. 点击链接前，账号的登录邮箱应仍是旧邮箱，不应提前生效。
  3. 点击链接后，登录邮箱变为新邮箱，用新邮箱可以登录。
03

用例二：旧邮箱与通知

  • 产品如果设计了给旧邮箱发送变更通知，检查旧邮箱是否收到、内容是否清楚。
  • 变更完成后，旧邮箱是否不能再用于登录或找回密码。
  • 确认邮件的数量正确，没有重复发送。
04

用例三：链接过期、重复点击与旧链接

  • 确认链接在设计的有效期之后失效，并给出明确提示。
  • 同一个链接点击两次，第二次应当给出合理提示，而不是报错。
  • 连续提交两次不同的新邮箱，先发的链接是否失效，应与产品规则一致。重发邮件相关的用例见重发验证邮件测试用例。
05

用例四：邮箱已被占用与格式问题

  • 输入已被其他账号使用的邮箱，应有明确提示，并且不泄露不该泄露的信息。
  • 输入与当前邮箱相同的地址、格式错误的地址、大小写不同的同一地址，检查结果是否一致。大小写等情形可参考重复邮箱注册测试用例。
06

用例五：登录状态与安全

  • 修改邮箱前是否要求再次输入密码或验证身份，这应与产品设计一致。
  • 在确认链接未点击时，账号其他功能是否正常。
  • 邮件里不应出现密码等敏感信息。
07

新邮箱没收到确认邮件怎么办

  1. 确认填写的地址与新收件箱完全一致。
  2. 在收件箱里手动刷新一次。
  3. 用接口轮询时记录空轮询次数，以区分“没发出”和“等得不够久”。
  4. 测完后删除邮件或清空收件箱，保持下一个用例干净。
08

常见问题

修改邮箱功能应该测哪些场景？

新邮箱验证、旧邮箱通知、链接过期与重复点击、邮箱已被占用、格式与大小写、登录状态与安全。

为什么需要两个临时邮箱？

一个充当旧邮箱注册账号，另一个接收新邮箱的确认邮件，这样能完整验证两端行为。

测试需要注册 CleanTempMail 吗？

手动查看邮件时，网页收件箱免费，无需注册。

能自动取信吗？

可以，CleanTempMail 提供付费的 REST API，见邮件测试 API 指南。

邮件会一直保留吗？

不会，邮件是临时的，不会永久保存。
