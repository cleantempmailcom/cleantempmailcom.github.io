邮件里的链接域名不对？验证邮件链接的测试清单

邮件内容看起来都对，点开链接却跳到了生产环境，或者 token 参数被截断、被转义——这类问题在联调时很常见，又特别容易漏测。这篇文章给出一份检查清单，说明每一类链接要核对什么，以及如何用临时收件箱在每次测试中拿到干净的邮件来核对。

01

为什么邮件链接值得单独测

邮件链接由后端拼接，依赖配置里的站点地址、路由和模板。环境变量没配好、模板里写死了域名、参数没做 URL 编码，都会让用户点到错误的页面。这些问题在接口测试里看不出来，只有拿到真正的邮件才会暴露。

02

必查的几类问题

  • 域名与协议：测试、预发布环境的邮件，链接应指向对应环境，而不是生产域名；协议应为 https。相关背景可参考预发布环境的测试邮件怎么管。
  • 参数完整性：token、邮箱、跳转地址等参数是否完整，特殊字符（加号、等号、&）是否被正确编码。
  • 纯文本与 HTML 两个版本：如果模板同时有两种内容，两处链接应一致。
  • 按钮与文字链接：按钮文字链接和“复制此链接”的明文地址是否指向同一处。
  • 一次性与时效：点击后的行为，参考一次性链接被预取的测试用例。
  • 多语言：不同语言版本的邮件链接是否带上了正确的语言参数。
03

用临时收件箱核对链接

  1. 生成测试地址：打开 CleanTempMail，无需注册，生成随机地址，或自定义有规律的前缀，便于区分用例。
  2. 触发邮件：用该地址走注册、重置密码等流程。
  3. 查看邮件：收件箱支持自动或手动刷新，打开邮件即可查看正文；需要时复制链接，核对域名与参数。
  4. 记录结果：把问题链接与对应环境一起记入用例结果。
  5. 清理：邮件是临时的，不会永久保存；用完可删除邮件或清空收件箱。

如果要把核对写进自动化，CleanTempMail 提供付费 REST API，思路见邮件测试 API 指南。

04

建议覆盖的用例

  • 各环境（开发、测试、预发布）分别触发邮件，核对链接域名。
  • 邮箱地址包含加号或点号时，链接参数是否正确。
  • 链接复制到新浏览器中打开，是否依赖已有登录状态。
  • 邮件里的外部图片被拦截时，链接是否仍然可用。CleanTempMail 带有追踪保护，会拦截外部图片。
  • 多次触发邮件，最新一封的链接是否生效。
05

减少漏测的习惯

把“邮件链接域名”写进发布前检查项；每次修改邮件模板或站点地址配置，都重新跑一遍邮件链接用例。每个用例使用独立的收件箱，避免旧邮件混淆结果。

06

常见问题

核对邮件链接需要注册 CleanTempMail 吗？

不需要。网页收件箱免费使用，无需注册。

可以用固定前缀的地址吗？

可以。CleanTempMail 支持随机地址，也支持自定义前缀。

邮件会一直保存吗？

不会。邮件是临时的，不会永久保存。

能在自动化测试里读取邮件吗？

CleanTempMail 提供付费 REST API，可用于自动化读取，具体套餐见官网。
