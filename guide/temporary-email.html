临时邮箱使用指南：
从第一次收信到自动化测试。

什么是临时邮箱？

临时邮箱是一种面向短期收信需求的工具。你可以创建一个地址，把它填入需要接收邮件的表单，然后返回收件箱查看消息。它适合产品体验、短期资料获取，以及你自己应用的邮件流程测试。

与日常邮箱相比，它的价值在于将临时需要与长期通信分开。临时地址不应成为重要账户的唯一找回方式，也不适合保存必须长期保留的资料。

如何开始收信？

打开 CleanTempMail 网页邮箱，创建随机地址或使用自定义前缀。从当前可用域名中选择一个地址，复制后用于本次流程，再回到官网查看消息。

  • 网页收件箱支持自动刷新与手动刷新。
  • 打开邮件可以查看正文、发件人及附件。
  • 你可以删除单封邮件，或清空收件箱。
  • 直达收件箱的链接便于返回对应地址；请谨慎分享收件箱链接。

具体域名池与界面功能以官网实时显示为准。部分服务会限制临时地址，请遵守对方的使用规则。

如果预期邮件没有出现，先按临时邮箱收不到邮件的排查步骤检查当前流程，再决定是否更换地址。

公共域名与自有域名怎么选？

短期体验可以使用官网提供的公共域名。如果你管理自己的域名，CleanTempMail 也提供自有域名接入：按官网说明将 MX 记录指向 mail.cleantempmail.com，然后在官网提交域名验证。

MX 记录决定邮件投递到哪里。配置前应确认该域名是否已有收信服务，使用独立子域名可以让测试需求更容易管理。接入条件请查看 官方域名说明。

需要按步骤配置时，可参考自有域名临时邮箱配置与验收清单，分别检查 DNS、域名验证和实际收信。

如何保护重要信息？

为短期流程选择临时地址，能减少向陌生服务提供常用邮箱的次数。官网收信界面的追踪保护可以阻止邮件加载外部图片；开启外部内容前，应考虑它可能向发件方透露访问信息。

重要账户、支付、长期通信和密码找回，请使用你长期掌控的邮箱。临时邮箱不代表绝对匿名，也不能替代账户安全设置。官方 服务条款与隐私说明 提供完整规则。

怎样把邮件测试加入自己的应用？

网页邮箱适合手动收信。需要自动验证注册、通知或附件时，可以使用付费 REST API：创建测试地址，触发自己应用的邮件，再轮询收件箱、读取正文或下载附件，最后清理测试邮件。

先通过官方 Quickstart 理解返回字段与接口，再将断言写入测试脚本。生产工作流应使用购买的独立密钥；共享测试密钥 ct-test 的额度由所有使用者共享。

一次性购买的是请求次数，不是订阅。密钥不能追加充值，需要更多次数时购买新密钥。具体套餐与接口以 官方 API 文档 为准。

临时邮箱 API 自动化测试指南进一步说明如何设置有限轮询、消息断言与清理步骤。

如何减少不必要的 API 消耗？

受保护请求在密钥通过认证后计次。空收件箱查询、重复轮询，以及部分参数错误仍可能消耗额度。查看剩余额度不扣次数。

假设每个测试最多等 120 秒，每 30 秒查一次收件箱，轮询是 4 次；加上生成地址、读取一封邮件和删除一封邮件各 1 次，合计约 7 次。100 个这样的流程约消耗 700 次。这是规划示例，实际消耗会随重试、邮件数量和额外操作变化。

  • 按测试需要设置合理的等待上限与查询间隔。
  • 记录已收到的邮件 ID，避免反复读取同一消息。
  • 处理超时与接口错误，避免无限轮询。
  • 将密钥放在服务端或 CI 的秘密配置中，不写进公开网页或仓库。
