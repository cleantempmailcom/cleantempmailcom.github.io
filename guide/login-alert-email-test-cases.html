01

为什么登录提醒要单独测

登录提醒不同于验证邮件：用户并没有主动“等”它，所以它出错时没人会抱怨，问题往往潜伏很久。常见的毛病有两类：该发的没发（漏报），不该发的发了一堆（刷屏）。

它还依赖“设备”“浏览器”“位置”等判断规则，测试时需要在同一个测试账号上反复制造“新设备”，因此一个随开随用、能立即看到邮件的收件箱会省很多事。

02

准备测试账号与收件箱

打开 CleanTempMail，免费生成一个临时邮箱地址（不必注册），可以使用随机前缀，也可以自定义前缀方便识别。用它注册测试账号，并完成邮箱验证（可参考注册验证邮件测试用例）。之后用不同浏览器、无痕窗口或另一台设备登录，就能制造“新设备”场景，在收件箱里观察提醒邮件。

03

测试用例清单

  • 首次在新设备登录：应收到提醒，收件人是账号邮箱，主题明确，内容包含登录时间、设备或浏览器信息（以你们的设计为准）。
  • 同一设备再次登录：不应重复发送，验证“已识别设备”的记忆是否生效。
  • 清除 Cookie 或换无痕窗口：按你们的规则判断是否算新设备，并确认实际行为与产品约定一致。
  • 登录失败：输错密码是否触发提醒？如果设计上不触发，确认没有发出；如果会触发，确认文案不同于成功登录。
  • 短时间内连续登录：多个新设备同时登录时，是合并成一封还是各发一封，应有明确约定，避免刷屏。
  • “不是我”链接：点击后应引导到修改密码或退出所有设备的页面；链接是否有有效期、能否重复使用也要测。可对照密码重置邮件测试清单。
  • 链接与环境：邮件里的链接域名、协议是否正确，预发布环境不要指向生产地址。
  • 邮件内容安全：邮件中不应出现密码、完整令牌等敏感信息。
  • 更换邮箱之后：账号邮箱修改后，提醒应发往新地址，而不是旧地址，参见修改登录邮箱测试用例。
  • 通知开关：如果用户可以关闭提醒，关闭后应不再发送，重新开启后恢复。
04

让测试更稳的几个小技巧

  • 每条用例使用独立的测试账号和独立收件箱，避免上一条用例留下“已识别设备”的状态。
  • CleanTempMail 支持自动或手动刷新，登录之后立即查看收件箱，对比邮件到达的时间是否合理。
  • 打开邮件后可以查看正文，用来检查文案、链接与排版；如果邮件含图片，注意临时邮箱会拦截外部图片的追踪，这也能顺带测试邮件在图片被拦截时是否仍然可读。
  • 需要自动化时，可使用付费 REST API 在测试脚本里轮询收信并取出链接。
05

把它放进自动化回归

登录提醒适合做成回归用例：脚本创建账号、用第二个浏览器上下文登录、轮询收件箱，断言邮件到达且内容符合预期。设置合理的等待超时，并在失败时输出收到的邮件列表，排查会快很多；邮件迟迟不到的情况可参考验证邮件迟迟没到怎么测。

06

常见问题

测试登录提醒邮件需要真实邮箱吗？

不需要。可以用 CleanTempMail 的临时收件箱接收提醒邮件，免费生成，不必注册。

怎么在本地制造“新设备”？

换一个浏览器、使用无痕窗口或另一台设备登录即可，具体是否算新设备取决于你们自己的判断规则。

可以自动化吗？

可以。CleanTempMail 提供付费 REST API，可在自动化测试中轮询收信并取出邮件内容。

临时收件箱里的邮件会一直保留吗？

不会。邮件是临时的，不会永久保存，需要留存的内容请自行保存。
