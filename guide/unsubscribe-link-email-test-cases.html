退订链接怎么测？营销邮件“取消订阅”的测试用例清单

退订链接常被当成“邮件底部的小东西”，上线后才发现点了没反应、退订后照发不误，或者链接指向了预发布地址。这份清单把它拆成可执行的测试用例，并用一次性收件箱把每个场景走一遍。

01

为什么退订链接值得单独测

退订是用户对订阅邮件最后的控制权。它出问题的代价不低：用户找不到退订入口只能点“垃圾邮件”，退订后继续收信则会引来投诉。而且它藏在邮件底部，很少有人在功能验收时认真点一遍。

测试它需要反复订阅、收信、点击，因此一个免费、无需注册、随时能新建的收件箱最合适。

02

准备测试订阅与收件箱

打开 CleanTempMail，免费生成一个临时邮箱地址，可使用随机前缀，也可自定义前缀方便区分用例。用它订阅你的测试邮件列表，并触发一封营销或通知类邮件（欢迎邮件的检查可参考注册欢迎邮件测试清单）。邮件到达后在收件箱打开正文，找到退订链接。

03

测试用例清单

  • 链接存在且显眼：每封营销邮件底部都应有退订入口，文字清晰，不是淡到看不见。
  • 链接可打开：域名、协议正确，预发布环境不要指向生产地址。
  • 退订生效：点击后再触发同类邮件，确认不再发送；注意是否区分“全部营销邮件”和“某一类邮件”。
  • 重复点击：同一链接点两次，第二次应给出友好提示而不是报错。
  • 确认页与反悔：如果有确认页，检查按钮文案；如果支持“重新订阅”，确认可以恢复。
  • 事务类邮件不受影响：退订营销邮件后，验证码、密码重置等必要邮件仍应正常发送。
  • 链接是否绑定身份：链接应只对应该订阅者，不能通过修改参数退订别人。
  • 图片被拦截时仍可用：临时邮箱会拦截外部图片，趁机确认退订入口是文字链接，而不是只放在图片里，参见图片拦截测试清单。
  • 多语言邮件：不同语言版本的退订文案和落地页语言应一致。
04

让测试更稳的几个小技巧

  • 每条用例用独立的收件箱和订阅，避免上一条用例的退订状态干扰下一条。
  • CleanTempMail 支持自动或手动刷新，退订后触发新邮件，等待一段合理时间再确认“确实没有收到”。
  • 退订成功的判断需要等待窗口，不要只看一瞬间，可在收件箱里清空旧邮件后再观察。
  • 需要自动化时，可使用付费 REST API 在脚本里轮询收信并取出退订链接。
05

放进自动化回归

流程可以脚本化：订阅、轮询收件箱、取出退订链接、访问它，再触发同类邮件并在超时后断言“没有新邮件”。负向断言容易误判，建议配合明确的等待时间并在失败时输出收到的邮件列表。邮件迟迟不到的排查可参考 验证邮件迟迟没到怎么测。

06

常见问题

测试退订链接需要真实邮箱吗？

不需要。可以用 CleanTempMail 的临时收件箱接收邮件，免费生成，不必注册。

怎么确认退订后真的不再发送？

退订后再触发同类邮件，等待合理时间，确认收件箱没有新邮件，同时确认必要的事务类邮件仍正常。

可以自动化吗？

可以。CleanTempMail 提供付费 REST API，可在自动化测试中轮询收信并取出邮件内容。

临时收件箱里的邮件会一直保留吗？

不会。邮件是临时的，不会永久保存，需要留存的内容请自行保存。
