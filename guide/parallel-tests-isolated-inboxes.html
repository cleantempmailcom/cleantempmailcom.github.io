并行测试总是收到别人的验证邮件？给每个用例一个独立临时邮箱

01

为什么共用收件箱会让并行测试偶发失败

典型症状：本地串行跑很稳，上 CI 并行后偶尔红。多个用例向同一个地址注册，每个用例都去“取最新一封邮件”，结果拿到的可能是别人的。重试之所以有效，只是因为时间错开了。

这类问题靠加大等待时间解决不了。等待策略可参考E2E 测试等验证邮件的稳定做法；这一篇解决的是更前面一步：让每个用例只可能看到自己的邮件。

02

原则：一个用例，一个地址，一个运行标识

  • 地址唯一。CleanTempMail 支持随机前缀，也支持自定义前缀。用“运行编号 + 用例名”拼出前缀，排查时一眼能对上。
  • 不复用。同一地址不要跨用例、跨重试使用，否则旧邮件会污染断言。
  • 断言要具体。不要只判断“收到了邮件”，还要检查收件地址、主题和正文里的验证码或链接。

需要把测试流量放在自己的域名下时，可以参考自有域名邮箱配置，通过 MX 指向 mail.cleantempmail.com 即可。

03

四步落地

  1. 生成唯一地址。在每个用例开始时，用运行编号加随机后缀生成前缀，组合成测试地址。
  2. 用它注册。把地址交给被测应用，触发验证邮件。
  3. 有限轮询。设置总超时和固定间隔，只读取这个地址的收件箱；超时就失败并输出地址，方便定位。
  4. 断言并清理。读取正文后提取验证码或链接，完成断言，再删除邮件或清空收件箱。

CleanTempMail 的付费 REST API 可以创建地址、读取邮件、下载附件、删除邮件，适合把这四步写进自动化。完整的轮询与断言设计见临时邮箱 API 测试指南。

04

把请求次数算进预算

API 按请求计数，受保护的请求在认证后就会计入，包括返回空结果的轮询。并行用例多、轮询间隔短，消耗会成倍增加。

  • 轮询间隔不要过短，设上限次数。
  • 每个用例只读自己的地址，避免全量扫描。
  • 官网目前提供的套餐为 Starter $3 / 1 万次、Growth $12 / 5 万次、Pro $39 / 20 万次、Business $149 / 100 万次，一次性购买，不自动续费。
  • 官网另有共享试用密钥 ct-test，额度与其他用户共享，只适合试跑，生产环境请使用自己购买的独立密钥。
05

需要知道的限制

临时邮箱里的邮件只是暂存，不会永久保存，所以断言完成后应及时把需要留存的证据（例如截图、验证码）保存到测试报告里。测试对象必须是你自己的应用或已获授权的环境；不要用它去批量注册第三方服务。

06

常见问题

并行测试可以共用一个临时邮箱吗？

不建议。共用地址时用例会读到彼此的邮件，导致偶发失败。让每个用例使用自己的地址更稳。

临时邮箱地址可以自定义前缀吗？

可以，支持随机前缀或自定义前缀，方便把运行编号写进地址。

轮询空结果也消耗 API 请求吗？

会。受保护的请求在认证后计数，包括空结果和重复轮询，所以要设置间隔和次数上限。

网页收件箱可以用来手动排查吗？

可以。网页收件箱免费，无需注册，可以输入失败用例的地址直接查看邮件。

测试邮件会一直保存吗？

不会。临时邮箱里的邮件只是暂存，不会永久保存。
