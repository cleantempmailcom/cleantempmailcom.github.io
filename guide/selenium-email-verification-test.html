Selenium 怎么测邮件验证码？注册验证流程的自动化做法

Selenium 能点按钮、填表单，却收不到邮件。注册验证码、确认链接这一段，往往成了自动化里最不稳的一环。这篇文章给出一套思路：每条用例用一个独立的临时邮箱，等邮件、取内容，再把浏览器带回流程。

01

为什么 Selenium 需要单独处理邮件

浏览器自动化只管页面内的事。验证邮件发到哪里、什么时候到、内容是什么，都在页面之外。常见的做法是共用一个测试邮箱，结果多条用例互相抢邮件，或者旧邮件干扰判断。

更稳的做法是：一条用例一个全新地址。地址不重复，收件箱里就只有这条用例触发的邮件。关于并行时如何隔离，可以参考并行测试的独立收件箱。

02

整体流程：五步

  1. 准备地址：每条用例开始时生成一个随机地址（CleanTempMail 支持随机或自定义前缀，也有多个域名可选）。
  2. Selenium 填表：把地址填进注册表单并提交。
  3. 等待邮件：在测试代码里轮询收件箱，直到出现目标邮件或超时。
  4. 提取验证码或链接：读取邮件正文，用正则取出验证码，或取出确认链接。
  5. 回到浏览器：把验证码填入页面，或让 driver 打开确认链接，再断言结果。

想在代码里自动读收件箱，可以使用 CleanTempMail 的 REST API（付费一次性密钥；也有共用测试密钥 ct-test 可先试用），详见邮件测试 API 指南。

03

等待策略：别用固定 sleep

  • 用轮询，不用固定等待：每隔几秒查一次收件箱，邮件到了立刻继续，既快又稳。
  • 设置总超时：超时就让用例失败，并在报错里写明地址和已等待时间，方便排查。
  • 空轮询也要算：API 的空轮询同样计入用量，轮询间隔不要太短。
  • 失败时留证据：超时后保留地址与页面截图，再到网页收件箱里看邮件是否真的没发。

邮件迟迟不到的更多测试思路见验证邮件迟迟没到怎么测。

04

提取验证码和链接的注意点

  • 正则要有边界：验证码通常是固定位数的数字，匹配时限定位数，避免取到邮件里别的数字。
  • 链接要取完整：确认链接常带长参数，取出后不要截断或二次编码。
  • 别让链接被提前消耗：如果用脚本先“访问”过链接，一次性链接可能已经失效，需要先想好谁来打开它。
  • HTML 与纯文本：先看邮件正文实际是哪一种，再决定怎么解析。
05

Selenium 里常见的坑

  • 复用地址：两条用例用同一地址，邮件会混在一起。
  • 重复提交：页面上点了两次发送，会收到两封邮件，断言时要明确取哪一封。
  • CI 里的时钟与网络：环境较慢时，超时要比本地宽松一些。
  • 站点拒绝某些域名：被测系统若屏蔽了部分域名，可以换一个 CleanTempMail 域名，或用自定义域名（通过 MX 指向 mail.cleantempmail.com）。
06

常见问题

Selenium 能直接读邮件吗？

不能。Selenium 只控制浏览器，需要在测试代码里另外读取收件箱，例如通过 CleanTempMail 的 REST API。

每条用例都要新地址吗？

建议如此。独立地址能避免邮件互相干扰，也方便并行执行。

REST API 要付费吗？

需要一次性密钥，按套餐计次；也可以先用共用的 ct-test 测试密钥试一试。

网页收件箱需要注册吗？

不需要，网页收件箱免费使用，无需注册，可用来人工核对邮件。
