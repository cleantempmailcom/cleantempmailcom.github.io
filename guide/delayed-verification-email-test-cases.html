验证邮件迟迟没到怎么测？延迟、超时与重试的测试用例清单

真实环境里，验证邮件并不总是秒到：队列拥堵、第三方发信服务限流、收件方延迟接收都可能让邮件晚几十秒甚至几分钟。测试时如果只覆盖“邮件马上到达”的理想情况，用户一遇到延迟就会卡在没有任何提示的页面。这篇文章整理一份延迟场景的测试用例清单。

01

为什么要专门测“邮件延迟”

验证邮件的发送是异步的：应用只是把任务交给发信服务，邮件什么时候到，并不由前端决定。因此页面必须在“还没收到”的这段时间里，给用户明确的状态、倒计时和下一步操作。

很多线上投诉并不是邮件没发，而是页面没有告诉用户“再等一等”，用户反复点击重发，最后收到好几封内容不同的邮件。

02

延迟场景的测试用例

  • 等待状态：提交注册后，页面是否显示“邮件已发送至某地址”的提示，而不是空白或无限加载。
  • 延迟到达：邮件晚到 30 秒、2 分钟时，验证链接或验证码是否仍然有效。
  • 超过有效期：邮件到达时验证码已过期，页面是否给出明确提示并提供重新获取入口。
  • 重发冷却：倒计时期间重发按钮是否禁用；冷却结束后重发是否可用，细节见重发验证邮件测试用例。
  • 新旧邮件并存：用户重发后，先发出的旧邮件迟到了，它的链接是否按预期失效。
  • 页面刷新与返回：等待中刷新或关闭页面再回来，状态能否恢复。
  • 填错邮箱：用户发现地址写错时，是否有修改邮箱的入口。
03

五步用临时收件箱核对延迟

  1. 准备专用地址：在 CleanTempMail 网页收件箱免费生成地址，无需注册，可随机也可自定义前缀，比如用例名加时间。
  2. 记录提交时间：在预发布环境用该地址提交注册，记下时刻。
  3. 观察收件箱：开启自动刷新，也可以手动刷新，记录邮件出现的时间，与提交时间对比。
  4. 验证页面表现：等待期间检查倒计时、提示文案和重发按钮是否符合预期。
  5. 清理：用完删除邮件或清空收件箱。需要脚本自动轮询时，可使用付费 REST API，思路见E2E 测试稳定等待邮件的做法。
04

自动化测试里怎么等邮件

不要用固定的长时间休眠，它既拖慢测试，又在邮件稍晚时失败。更稳妥的是设置一个合理上限，在上限内按固定间隔轮询收件箱，邮件一到就继续。超过上限仍没有邮件，让测试明确失败并输出提交时间、使用的地址，方便排查。

CleanTempMail 的 API 把空轮询也计入用量，所以轮询间隔不要设得过密，具体套餐与额度见官方页面。如果邮件长时间不出现，也可以参考收不到邮件的排查思路。

05

需要注意的边界

临时收件箱只能帮你观察“邮件何时出现”，无法人为制造发信延迟；要模拟延迟，需要在预发布环境的发信服务或队列里调整。另外，CleanTempMail 的邮件是临时的，不会永久保存，需要留存的证据请自行另存。

06

常见问题

验证邮件一般该等多久再提示用户？

没有统一标准，取决于你的发信服务。建议在页面上提示邮件可能需要一点时间，并在冷却结束后提供重发入口。

可以用临时邮箱测延迟吗？

可以，用它观察邮件实际出现的时间，并核对页面表现。

需要注册 CleanTempMail 吗？

网页收件箱免费，无需注册。

自动化脚本能轮询收件箱吗？

可以使用付费 REST API，详见 API 测试指南和官方文档。

邮件会一直保留吗？

不会。邮件是临时的，不会永久保存。
