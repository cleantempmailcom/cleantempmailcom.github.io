Cypress 怎么测邮件验证码？用 cy.task 加独立临时邮箱的做法

Cypress 的测试代码跑在浏览器里，不适合直接带着密钥去查邮件，也没有内置的收信能力。想测“注册后收验证码、再填回页面”的流程，常见做法是把取信交给 Node 端的 cy.task。这篇文章说明这套结构、每一步该注意什么，以及如何避免用例互相干扰。

01

为什么 Cypress 里要用 cy.task 取信

Cypress 的 spec 在浏览器环境运行，而读取邮件需要调用带密钥的服务端接口。把密钥写进 spec 或暴露给页面代码并不安全。cy.task 在 Node 进程中执行，适合承担“查询收件箱”这件事，spec 只拿到结果。

CleanTempMail 的网页收件箱免费、无需注册，适合手工核对；要在代码里读信，需要使用付费 REST API。下面的示意不假设任何具体的接口路径或字段，请以官方 API Quickstart 为准来编写适配器。

02

第一步：每个用例一个独立地址

在用例里用时间戳加随机数生成唯一前缀，例如 cy-login- 后接随机串。这样并行或重试时，不会读到别的用例的邮件。为什么必须隔离、怎么隔离，可以看并行测试的独立收件箱做法。若需要固定使用你自己的域名，参见自定义域名指南。

03

第二步：把取信写成 cy.task 与有限次轮询

下面是示意代码，重点在结构，不在接口细节：

// cypress.config.js （示意：fetchMessages 是你按官方 API 文档写的适配器）
const { defineConfig } = require('cypress');
const { fetchMessages } = require('./support/mail-adapter');

module.exports = defineConfig({
  e2e: {
    setupNodeEvents(on) {
      on('task', {
        async getEmail({ address }) {
          const msgs = await fetchMessages(address); // 在 Node 端调用，密钥只在这里出现
          return msgs.length ? msgs[0] : null;       // null 表示“还没到”
        },
      });
    },
  },
});

// spec
const address = `cy-login-${Date.now()}-${Cypress._.random(1e4)}@your-domain`;
cy.visit('/login');
cy.get('[name=email]').type(address);
cy.contains('button', '发送验证码').click();
function waitForMail(n = 0) {
  if (n > 15) throw new Error('timeout: 未收到邮件');
  return cy.task('getEmail', { address }).then((m) => m || cy.wait(4000).then(() => waitForMail(n + 1)));
}
waitForMail().then((m) => { /* 断言收件人、主题，提取验证码 */ });

要点：任务返回 null 代表“还没到”，不是通过；轮询次数和间隔有明确上限（这里最多约 60 秒）；超时要抛出明确的错误。不要用固定的 cy.wait(10000) 代替轮询，它要么太短导致不稳定，要么太长拖慢流水线。

04

第三步：断言邮件属于这一次用例

  • 收件人等于本次生成的唯一地址。
  • 主题或发件人符合预期，而不是“有一封邮件”就算通过。
  • 验证码的位数和字符格式正确，再填入表单。
  • 验证链接的主机名属于你的测试环境，才去访问。

注册、重发、重复注册等更多场景的断言，见验证邮件测试用例清单。

05

第四步：放进 CI 之前

密钥放进 CI 的密钥配置，只在 Node 端的 task 中使用，不要写进仓库、查询参数或日志。官网上的共享试用密钥只适合试一试，不是持续测试可依赖的额度。付费 API 的每次轮询都会计入请求额度，包括返回空结果的轮询，所以间隔不要设得太密。

失败时先保存脱敏的证据（用到的地址、等待时长、最后一次轮询返回的邮件数量），再清理。只在你自己的产品和测试环境上使用，并遵守第三方站点的规则。

06

常见问题

Cypress 能直接在 spec 里读邮件吗？

不建议。读邮件需要带密钥的接口调用，放到 cy.task 的 Node 端执行更安全，spec 只接收结果。

用 cy.wait 固定等几秒行不行？

不推荐。固定等待要么太短导致用例不稳定，要么太长拖慢流水线；有限次轮询在邮件到达后就能继续。

轮询会消耗额度吗？

使用付费 API 时会，空结果的轮询也计入请求额度，所以请设置合理的间隔和上限。

手工验证可以用网页收件箱吗？

可以。网页收件箱免费且无需注册，适合手工核对；在代码里读信则使用官方 API。

Playwright 或 Selenium 也适用吗？

适用。核心都是唯一地址、有限次轮询和精确断言，与框架无关。
