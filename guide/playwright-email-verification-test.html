Playwright 怎么测邮件验证码？注册验证流程的端到端测试做法

Playwright 能点按钮、填表单，却收不到邮件。注册验证码、确认链接这一段，需要一个测试能自己创建、自己读取的收件箱。这篇文章讲清整个流程的结构，以及容易踩的坑。

01

为什么端到端测试卡在“收邮件”这一步

注册流程里最难自动化的往往不是表单，而是邮件：测试要拿到一个能收信的地址，等邮件到达，再从正文里取出验证码或链接。用固定的真实邮箱会让多个用例互相抢信，用共享邮箱又容易读到旧邮件。

更稳的做法是每个用例使用独立的一次性收件箱。CleanTempMail 的网页收件箱免费、无需注册，可用来先手动走通流程；需要写进脚本时，可使用付费 REST API。

02

先手动走通一遍

在写任何代码之前，先打开 CleanTempMail，生成一个地址（随机前缀或自定义前缀），用它在你的测试环境注册，观察邮件多久到达、正文长什么样、验证码或链接在哪里。这一步能确定脚本要匹配的内容，也能顺便发现邮件本身的问题。

03

测试脚本的基本结构

  • 创建地址：每个用例开始时生成独立地址，用例名可放进自定义前缀，便于排查。
  • 填表提交：用 Playwright 在注册页填入该地址并提交。
  • 轮询收件箱：设置总等待时间和轮询间隔，到点前不断查询，收到邮件立刻停止。
  • 取出验证码或链接：从正文用正则或解析取出内容。
  • 回到页面完成验证：填入验证码，或用 page.goto 打开确认链接，再断言登录状态。
  • 清理：用例结束删除测试邮件。

等待邮件时要用明确的超时和重试，而不是固定 sleep。每次轮询在付费 API 下都会消耗请求额度，空收件箱也计费，所以间隔别设得太短。

04

别只测“成功”这一条

  • 输错验证码、验证码过期后的提示，可参考验证码登录测试用例。
  • 点击“重新发送”后只有最新一封有效。
  • 验证链接被打开两次的表现。
  • 邮件未到达时页面是否给出清晰提示。
05

并行执行时的注意事项

Playwright 默认可多个 worker 并行。只要每个用例都有自己的收件箱，就不会读到别人的邮件；反过来，如果几个 worker 共用一个地址，就会出现偶发失败，详见并行测试总是收到别人的验证邮件。同样的思路也适用于 Cypress，参见Cypress 邮件验证码测试。

06

失败时怎么排查

  • 失败时把收件箱里已有邮件的主题打印出来，区分“没发”和“发了但没匹配上”。
  • CleanTempMail 的收件箱会拦截外部图片，不影响取文字验证码，但若验证码只放在图片里，脚本将无法读取。
  • 先用共享测试密钥 ct-test 熟悉接口；它的额度与其他用户共享，正式的 CI 请使用自己购买的独立密钥。
07

常见问题

Playwright 测邮件验证需要真实邮箱吗？

不需要。用 CleanTempMail 的临时收件箱即可接收验证邮件，免费生成，不必注册。

怎么在脚本里自动收信？

可使用 CleanTempMail 付费 REST API 创建地址并轮询收件箱、读取正文。

可以多个用例并行吗？

可以，前提是每个用例使用独立地址，避免互相读取对方邮件。

临时收件箱里的邮件会一直保留吗？

不会。邮件是临时的，不会永久保存。
