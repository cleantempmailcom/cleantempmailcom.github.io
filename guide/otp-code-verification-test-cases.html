验证码登录怎么测？过期、输错与重复发送的测试用例清单

用邮件发送 6 位验证码来注册或登录，看起来简单，边界情况却不少：过期、输错、连续请求、旧码是否还能用。本文给出一份可直接照着写的测试用例清单，并说明如何为每个用例准备一个独立的临时收件箱来收码。

01

先准备：每个用例一个独立收件箱

验证码测试最常见的问题是“收到了别的用例的码”。做法是每个用例生成一个独立地址：CleanTempMail 的收件箱可以随机生成，也可以自定义前缀，前缀里带上用例名或运行编号，便于排查。手动测试时直接用网页收件箱，它免费且无需注册，会自动刷新，也能手动刷新，并可以查看邮件正文。

自动化场景的隔离思路见并行测试的独立收件箱，通过接口收信见邮件测试 API（REST API 为付费一次性密钥，另有共享的 ct-test 密钥可供试用）。

02

用例一：验证码过期

  • 请求验证码后，在有效期内输入，应当成功。
  • 超过有效期后输入同一个码，应当提示过期，而不是“码错误”，两种提示不要混用。
  • 过期后点击重新发送，应能收到新码并成功验证。

有效期长短以你的产品需求为准，测试时请把它作为配置读取，不要在用例里写死。

03

用例二：输错与次数限制

  • 输错一次，应提示错误并允许再试，输入框不应被清空到无法重新输入。
  • 连续输错到你设定的上限后，应出现锁定或要求重新获取验证码，具体策略以需求为准。
  • 位数不对、含空格或字母的输入，应在前端或后端被友好拒绝。
04

用例三：重复发送与旧码失效

  • 连续点击发送两次，收件箱里应有两封邮件，比对两封里的验证码。
  • 按你的设计验证：旧码是否立即失效，只有最新的码有效，还是都有效。无论哪种，行为必须一致且可预期。
  • 重发按钮的冷却时间是否生效，可参考重发验证邮件测试清单。
05

用例四：同一个码不能用两次

验证成功后，再次提交同一个码应被拒绝。这条常被漏掉，建议每次成功用例后立即补一步重放。

06

收码失败时的排查顺序

  1. 确认收件地址与表单中填写的完全一致。
  2. 在收件箱手动刷新一次，查看是否有邮件。
  3. 用接口轮询时，记录空轮询的次数，这能帮你区分“邮件没到”和“代码没等够”。
  4. 仍然没有，再按邮件没收到的排查指南检查。

常见问题

邮箱验证码怎么测试？

覆盖有效期内成功、过期、输错、连续输错、重复发送、旧码失效和同码重放这几类用例，每个用例使用独立收件箱收码。

测试验证码需要注册 CleanTempMail 吗？

手动使用网页收件箱无需注册，免费使用。

验证码邮件总是收到别的用例的码怎么办？

为每个用例使用独立地址，前缀中带上用例名或运行编号。

可以用接口自动收验证码吗？

可以，CleanTempMail 提供付费 REST API，详见邮件测试 API 指南。
