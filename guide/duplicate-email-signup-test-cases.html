重复邮箱注册怎么测？同一邮箱二次注册与大小写的测试用例清单

“该邮箱已被注册”看起来是最简单的校验，却最容易出线上问题：大小写不同的同一地址能重复注册吗？第一次没验证，第二次再注册会怎样？这篇文章给出一份可直接落地的用例清单，并说明如何用独立的临时收件箱让这些场景稳定复现。

01

为什么重复注册值得单独测

重复注册校验同时牵涉前端提示、后端唯一约束和邮件发送三件事，任何一环有偏差都会出问题：

  • 只在前端提示，后端没有唯一约束，并发请求会产生两个账号；
  • 提示语过于具体，可能泄露“这个邮箱已经注册过”的信息，需要和产品决定是否接受；
  • 已注册地址再次提交时，到底发不发邮件，行为不一致会让用户困惑。

测试的前提是有大量互不干扰的真实可收信地址，这正是临时邮箱的用武之地。

02

测试用例清单

  1. 同一邮箱二次注册（已验证）：第一次注册并完成验证，第二次用相同地址提交，应得到明确、一致的提示，且不会创建新账号。
  2. 同一邮箱二次注册（未验证）：第一次注册后不点验证链接，直接再注册一次。预期行为由产品定义：覆盖旧账号、提示去验证，或重发邮件。检查旧验证链接是否仍有效，可对照重发验证邮件的测试清单。
  3. 大小写差异：用 Test@ 与 test@ 开头的同一地址各注册一次，检查系统是否把它们视为同一邮箱。
  4. 前后空格：在地址首尾加空格提交，检查是被去除后校验，还是直接报格式错误。
  5. 并发提交：同一地址几乎同时发出两个请求，检查数据库唯一约束是否生效，不应出现两个账号。
  6. 已注册地址收到什么邮件：检查已注册地址再次注册时是否收到邮件、内容是什么，并与产品约定的行为对照。
  7. 不同地址互不影响：另开一个全新的临时邮箱注册，应当完全正常，不受前面用例留下的数据影响。
03

用独立临时邮箱稳定复现

CleanTempMail 的网页收件箱免费，无需注册，地址可以随机生成，也可以自定义前缀。做重复注册测试时，建议这样安排：

  • 每个用例一个地址：用带用例编号的自定义前缀，例如 dup-01、dup-02，失败时一眼就能对应到用例，思路与并行测试的独立收件箱一致。
  • 同一用例内复用同一个地址：二次注册用例需要重复使用同一地址，直接在同一收件箱里观察两封邮件的先后与内容。
  • 查看邮件正文：收件箱可以查看正文和附件，也支持手动或自动刷新，方便核对每次提交到底发了几封邮件。
  • 用完清理：支持删除和清空邮件，下一轮开始前清空，避免旧邮件造成误判。
04

接入自动化

想把这些用例放进 CI，可以使用 CleanTempMail 的 REST API 轮询收件箱，细节见邮件测试 API 指南。API 是付费的一次性购买密钥（Starter $3 / 1 万次起），也提供共享的 ct-test 密钥用于体验。需要注意：空轮询同样计入次数，所以断言“没有收到邮件”类用例（例如已注册地址不应再收到邮件）要设置合理的等待时间，不要高频空轮询。

05

常见问题

重复邮箱注册应该提示“邮箱已被使用”吗？

这是产品与安全的取舍：明确提示体验更好，但可能泄露邮箱是否注册过。测试时先确认产品的约定，再验证行为是否一致。

怎么测试“没有收到邮件”？

在合理的等待时间后确认收件箱为空即可。若使用 API 轮询，空轮询也会计入次数，请控制频率。

需要注册 CleanTempMail 吗？

网页收件箱免费，无需注册。

临时邮件会永久保存吗？

不会。邮件是临时的，测试数据请在用例内消费完毕。
