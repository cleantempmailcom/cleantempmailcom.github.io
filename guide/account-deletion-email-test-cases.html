账号注销邮件怎么测？确认链接、冷静期与重新注册的测试用例清单

“删除账号”是最不常被测、出了问题却最麻烦的功能之一：确认邮件没发出，用户删不掉；链接可被他人利用，账号被误删；注销后同一邮箱再注册又出错。这份清单把注销流程里与邮件相关的环节拆成测试用例，并用一次性收件箱把整条流程反复走通。

01

为什么注销流程值得单独测

注销是破坏性操作，产品通常会加几道保险：先要求重新输入密码，再往账号邮箱发一封确认邮件，有的还设置几天“冷静期”，期间可以撤销。每一道保险都对应一封邮件或一个链接，也就对应一组需要验证的状态。

另一个特点是：它几乎总要用到“一次性”的测试账号。账号测完就被删掉，下一轮测试还要再注册一个，所以测试邮箱最好能随用随开、互不干扰。

02

先把流程画成状态图

不同产品的细节不一样，但大体都能归到下面几个状态，建议先和产品、后端对齐，再写用例：

  • 正常：账号可用。
  • 待确认：用户点了“删除账号”，系统已发出确认邮件，但对方还没点链接。
  • 冷静期（如果有）：已确认，数据暂未清除，可以撤销。
  • 已注销：登录、找回密码、旧链接都不应再生效。

每个状态之间的转换（确认、撤销、过期）就是你的用例骨架。

03

测试用例清单

  • 确认邮件送达：点击“删除账号”后应收到邮件，收件人、主题、账号标识都正确；可对照注册验证邮件测试用例里的检查项。
  • 确认链接生效：点击后进入明确的确认页面，而不是直接静默删除；二次确认文案要写清后果。
  • 确认链接过期：超过有效期后点击，应提示过期并说明如何重新发起。
  • 确认链接重复点击：第二次点击不应报错崩溃，应提示“已处理”或“账号已注销”。
  • 重复发起注销：连续点两次“删除账号”，应只留下一条有效请求，旧链接是否失效要有明确约定。
  • 登录状态：用另一台设备或无痕窗口打开确认链接，行为应符合设计（要求先登录，还是链接本身即可确认）。
  • 冷静期撤销：撤销后账号应完全恢复，收到“已撤销”的通知，原有数据不丢失。
  • 注销完成通知：最终注销后是否发送告知邮件，邮件里不应再带可登录的链接。
  • 注销后各入口：用旧密码登录、点击“忘记密码”（可对照密码重置邮件测试清单）、使用旧的验证或邀请链接，都应得到合理提示，且不泄露该邮箱曾注册过的更多信息。
  • 同一邮箱重新注册：注销完成后，用同一个邮箱再次注册，应该能走通新的验证流程，或者按产品规则明确提示（比如保留期内不可重用）。这一条和重复邮箱注册测试用例直接相关。
04

用临时收件箱走完整流程

  1. 新建地址：在 CleanTempMail 网页收件箱生成随机地址，或设置自定义前缀，例如 delete-case-1，无需注册。
  2. 注册测试账号：用这个地址注册并完成邮箱验证，确认账号可正常登录。
  3. 发起注销：在产品里点击删除账号，回到收件箱手动或自动刷新，等待确认邮件。
  4. 检查邮件：打开邮件查看正文与链接，核对收件人、文案和链接域名。
  5. 点击确认：按用例走“确认”或“过期”“重复点击”等分支。
  6. 回头再用同一个地址注册：验证“同一邮箱重新注册”这条用例。收件箱地址不变，所以可以直接再收一封新的验证邮件。
  7. 清理：测完删除邮件或清空收件箱，再为下一条用例换一个新地址。

CleanTempMail 还支持复制直达收件箱的链接，方便把同一个测试地址交给同事复现。

05

放进自动化回归

注销流程适合做成端到端回归用例：注册 → 验证 → 注销 → 确认 → 再注册。自动化时可以用邮件测试 API 轮询收件箱，取出确认链接再继续断言；每条用例使用独立地址，并行执行时也不会抢信。别忘了给轮询设置超时，空轮询同样会计入请求额度。

06

常见踩坑

  • 只测“点了删除就删”：忽略确认邮件、过期和重复点击这些分支。
  • 确认链接可被他人利用：链接应绑定当前账号与有效期，不能只靠一个可猜测的编号。
  • 注销后邮箱被永久占用：用户无法再次使用同一邮箱注册，却没有任何提示。
  • 测试数据没清理：在预发布环境可参考预发布环境测试邮件管理，避免测试账号收发真实邮件。
07

常见问题

测试账号注销邮件，需要真实邮箱吗？

不需要。可以用 CleanTempMail 的临时收件箱接收确认邮件，免费生成，不必注册。

注销后能用同一个临时邮箱地址重新注册吗？

可以用同一个地址再次注册，收件箱地址本身不变；至于产品是否允许重用，取决于你们自己的注销规则，这正是需要测试的地方。

可以把注销流程自动化吗？

可以。CleanTempMail 提供付费 REST API，可在自动化测试中轮询收信，取出确认链接。

临时收件箱里的邮件会一直保留吗？

不会。邮件是临时的，不会永久保存，需要留存的证据请自行保存。
